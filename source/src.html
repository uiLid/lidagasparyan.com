10Web dashboard

Navigation, account and billing screens for a WordPress website builder and hosting platform with AI tools.

Platform
10Web, a WordPress website builder and hosting platform
Discipline
Product design, interface design
Scope
Navigation, accounts and workspaces, security, billing, onboarding, payments
Screen sizes
1280 px and 1920 px

What the design had to hold

One left menu lists ten product areas. The Ecommerce area adds ten more pages. On top of that sit account settings, billing, users and several workspaces with different roles. The system had to keep all of it within reach without a crowded menu.

Problems and fixes

From my Workspace improvement write-up on Behance. These designs were tested and prepared for future implementation, and did not go live.

  • Complex left menu. The side menu lacked a clear hierarchy, so key tools were hard to find. I grouped related actions and improved visual contrast. Impact: faster navigation, lower cognitive load and a cleaner interface.
  • Live and staging environments. Moving between staging and live sites had an unclear workflow. I refined the UI with clearer state indicators, direct action buttons and better feedback messages.
  • Multiple sites and accounts. Users managing several sites struggled with workspace organisation. I designed workspace switching, role-based access and multi-account views to allow for growth.

Also in the file

  • Billing in four tabs: Subscription plan, Billing details, Payment methods and Invoices
  • A workspace page with workspace information and an access list by role
  • Personal information and account settings
  • Layouts at 1280 px and 1920 px, with the menu collapsed and expanded

10Web AI Co-Pilot

An assistant inside the 10Web website editor that lets people select an element, describe a change in plain words and judge the result.

Product
10Web AI Co-Pilot, in its Alpha release
Discipline
Product design, interface design, AI interaction
Scope
UX research, interaction design, usability testing; introduction, element selection, fast-edit toolbar, feedback flow
Duration
First iteration 3 months, second iteration 2 months
Tools
Figma, Notion, AI Analytics, Google Data Studio
Team
Project managers, AI engineers, developers, QA
Screen size
1280 px
Problem

Managing a website, from SEO to security, takes technical skill that many site owners do not have.

Solution

An AI assistant inside the editor: select an element, describe the change in plain words, judge the result.

Reported result

40% workflow boost, 50% fewer mistakes and 70% growth in AI adoption.

Context

10Web is an AI-powered WordPress platform with an AI website builder, hosting and an Elementor-based editor. The Co-Pilot is the assistant inside that editor. Per the 10Web help centre, people edit by describing changes in plain language, and it is on by default for sites created after November 2024.

10Web help centre: Co-Pilot editor ↗

Overview and goals

Many users struggle with website management, from optimising SEO to keeping a site secure. The aim was an AI assistant that simplifies those workflows without requiring technical expertise.

  • Automate repetitive workflows. AI-powered task execution reduces manual workload.
  • Enhance decision-making. Smart insights help users optimise their digital content.
  • Improve accuracy and consistency. AI-driven error detection and fixes streamline content management.

How it was designed

Research found the main barriers people face when managing digital workflows. The Co-Pilot was designed so that automation supports user decision-making and does not replace it.

  • User research. Interviews and AI behaviour tracking.
  • Prototyping. AI-powered suggestions that streamline tasks.
  • Testing and refinement. Iterations based on usability testing and feedback.

A competitive review against Wix AI, Shopify AI and WordPress AI compared four capabilities: AI-generated website insights, performance optimisation, AI content recommendations and one-click fixes for website errors. In that review, no single competitor covered all four, and the Co-Pilot did.

Key design decisions

  1. Start from a selection, not a blank prompt. The chat opens with one instruction, select the widget to change, so people always know the first move.
  2. Put the AI where the element is. An Ask AI field sits above the selected element, so people stay on the canvas.
  3. Suggest what to ask. Chips such as Simplify, Make longer and Fix grammar for text, and New image or Remove background for images, remove the guesswork of prompting.
  4. Adapt the toolbar to the element. Text shows heading level, font, size, style and colour. Images show upload, alignment and colour. Both keep Ask AI, copy and delete.
  5. Design every state. Default, hover, active, inactive and loading are drawn for each control, and the prompt field grows with long text up to a set maximum.

Reported results

These figures come from my published write-up of this project on Behance.

Faster execution40% workflow boost

AI automation reduced task completion time.

Higher accuracy50% fewer mistakes

AI-driven fixes minimised errors and misconfigurations.

Smarter decisions70% AI adoption growth

Users trusted AI suggestions, which increased adoption.

What comes next

The Alpha covers widgets and sections. The 10Web help centre lists page-level and full-website editing as planned updates, which the select, describe, evaluate loop is built to carry.

Home/Design system

Atomic design · v1

Design system

The tokens and components this site is built from, in atomic-design order: tokens, atoms, molecules, organisms, templates and pages. Every sample below is the live component, so it follows the theme switch in the header.

Principles

  • Show the work first. Screens carry the story. Interface chrome stays black, white and grey, and the one blue accent is kept for actions and current state.
  • One route to everything. Four destinations and one action in the header: Work, About, Design system, Contact, and Book a call. Case studies live under Work and link to each other.
  • Say where you are. The current page is marked in the header, every inner page has a breadcrumb, and case studies end with previous and next links.
  • Same template every time. Each case study uses one structure: summary, facts, screens with captions, next study. Readers learn it once.
  • Readable by default. Body text is 17 px at about 65 characters per line, contrast holds in light and dark, targets are at least 44 px, and focus is always visible.
